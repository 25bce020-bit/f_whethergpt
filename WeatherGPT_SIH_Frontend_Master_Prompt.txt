WEATHERGPT — SIH FRONTEND MASTER PROMPT
================================================

ROLE
----
You are a senior frontend architect, UI/UX designer, motion designer, and React engineer building the production-quality frontend for an SIH (Smart India Hackathon) project called "WeatherGPT".

Build a polished, modern, futuristic weather intelligence platform rather than a generic weather website. The frontend must feel like a serious SIH-winning product: visually impressive during a live demo, intuitive for normal users, responsive on phones/laptops, accessible, performant, and structured so the backend APIs can be connected without rewriting the UI.

IMPORTANT:
- Do not create a collection of disconnected demo screens.
- Build one coherent application with a consistent design system.
- Do not invent backend endpoints. Keep API integration in a dedicated service layer and make endpoint names/configuration easy to replace.
- Every feature must have loading, empty, error, and success states where applicable.
- Use realistic weather data models and clearly distinguish live data from placeholder/mock data.
- Avoid excessive visual effects that reduce readability or performance.
- The final result must be impressive but usable.

================================================
1. PRODUCT VISION
================================================

WeatherGPT is an AI-powered weather intelligence assistant.

The application should combine:
1. Current weather information.
2. Hourly and daily forecasts.
3. Weather alerts and warnings.
4. Location-aware weather.
5. AI-powered natural-language weather assistance.
6. Multilingual interaction.
7. Multilingual voice input/output.
8. Data visualizations.
9. Maps/location context.
10. A modern interactive interface capable of presenting complex weather information simply.

The frontend should make the AI/weather experience feel like one unified product rather than a weather dashboard with a chatbot attached.

30. BACKEND-READY DATA FLOW
================================================

The frontend should be prepared for the planned backend architecture.

Conceptual flow:

USER
  ↓
FRONTEND
  ↓
API SERVICE LAYER
  ↓
BACKEND
  ↓
WEATHER / AI / LOCATION / VOICE SERVICES
  ↓
NORMALIZED RESPONSE
  ↓
FRONTEND STATE
  ↓
UI

For AI:
User → Chat UI → AI API → response → message renderer

For voice:
Microphone → speech input → backend/service → AI → speech output → audio player

For weather:
Location → weather API → normalized weather state → dashboard

Do not assume every external provider is called directly from the browser.
